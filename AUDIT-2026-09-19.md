## الخلاصة التنفيذية

لم تظهر ثغرة High/Critical جديدة في الفحص الحالي. تم تنفيذ خمس نقاط كانت لا تزال مفتوحة أو غير محروسة:

1. **تقليل تسريب بيانات التحليلات:** لم تعد query strings أو hash أو إدخالات بحث واضحة على هيئة هاتف/بريد/رابط تُرسل إلى analytics.
2. **إزالة source-validation no-op:** `npm run test:sources` يفشل الآن برمز 2 عند غياب marker بدلاً من نجاح شكلي لا يفحص شيئاً.
3. **إغلاق فجوة شبكة الموضوعات:** كان المنتج `m-62` والمقال `royal-honey-benefits` خارج topic authority رغم كونهما محتوى قابلاً للربط. أضيفا إلى الموضوع المناسب، وأضيف حارس integrity يمنع تكرار العزلة.
4. **إغلاق تسريب PII في outbound analytics:** روابط واتساب الخاصة بالطلب تحمل بيانات العميل داخل `?text=`؛ أصبحت analytics تسجل origin/path فقط.
5. **توحيد health endpoint:** كان `/health` في Express يفتقد `Cache-Control: no-store` و`X-Robots-Tag` رغم وجودهما في Vercel؛ تمت مطابقة السلوكين.

## الإصلاحات المنفذة في هذه المرحلة

### P1 — منع تسريب query/PII إلى analytics — تم الإصلاح

**الدليل:** `src/lib/analytics.ts:74-96, 160-176, 247-249` و`src/routes/__root.tsx:160-164`.

- `page_location` و`page_referrer` أصبحا path/origin بدون query أو hash.
- referrer الفارغ يبقى فارغاً ولا يتحول إلى أصل الصفحة.
- كلمات البحث تُقص إلى 100 حرف وتحجب الأنماط الواضحة لأرقام الهاتف والبريد والروابط.
- RouteHeadSync يقرأ `q` فقط بدلاً من تمرير كامل query string بما فيه tracking parameters.
- أضيفت اختبارات للـ location/referrer وphone redaction ومصطلحات البحث العربية.

### P2 — source validator كان ينجح دون فحص — تم الإصلاح

**الدليل:** `scripts/validate-article-sources.mjs:8-27`.

- غياب `.generated-article-slug` أو كونه فارغاً ينتج الآن exit code `2` ورسالة صريحة.
- أضيف guard في `scripts/data-integrity.test.mjs:784-797` يمنع عودة السلوك الصامت.
- التشغيل المحلي المقصود بدون marker:

```text
❌ No generated article marker found ... Refusing a successful no-op ...
test:sources exit=2
```

- هذا لا يدّعي أن claims القديمة خضعت لمراجعة Gemini؛ فحص corpus المستقل لا يزال `npm run check-source-links`.

### P1 — تسريب نص طلب واتساب إلى analytics — تم الإصلاح

**الدليل:** `src/lib/analytics.ts` و`src/__tests__/analytics.test.ts`.

`GlobalTrackers` كان يمرر `u.href` كاملاً إلى `trackOutboundClick`. رابط واتساب الخاص بالطلب يحتوي `?text=` يتضمن اسم العميل ورقمه وعنوانه. أصبحت الدالة تزيل query/hash وتسمح فقط بـ HTTP(S) origin/path، مع اختبار يثبت عدم وصول رقم الهاتف إلى payload.

### P2 — اختلاف cache/indexing في `/health` بين Express وVercel — تم الإصلاح

**الدليل:** `server/index.js` و`api/health.js`.

فحص Express أظهر `200` بدون `Cache-Control` بينما endpoint Vercel كان `no-store`. أضيف `no-store` و`X-Robots-Tag: noindex...` إلى مسار Express، وأضيف guard في `scripts/data-integrity.test.mjs`.

**الدليل:** `src/data/topics.ts:95` و`:223`، وحارس `scripts/data-integrity.test.mjs:304-321`.

- أضيف `m-62 / halpeno-men-gel-50gm` إلى موضوع تأخير القذف.
- أضيف `royal-honey-benefits` إلى موضوع المكملات والعسل.
- أضيف تحقق صريح من أن كل المقالات وكل المنتجات الحالية لها topic assignment.
- النتيجة الحالية: `58 articles + 79 products assigned`.
- قبل الإصلاح كان المنتج `m-62` هو المنتج الوحيد غير المسند، والمقال `royal-honey-benefits` هو المقال الوحيد غير المسند.

## جرد dead code والملفات غير المتوقعة

شُغّل Knip على الملفات/exports/dependencies. أبلغ عن ملفات تبدو غير مستوردة، لكن التحقق اليدوي أثبت أنها ليست dead code:

- `api/health.js`: route serverless فعلي، ومذكور في rewrite `/health` داخل `vercel.json`.
- `api/errors.js`: يُركّب صراحة في `server/index.js` ويطابق `/api/errors`.
- `public/scripts/css-swapper.js` و`public/scripts/recently-viewed-shell.js`: يحقنهما prerender/critical-CSS داخل HTML المولّد، لذلك لا يظهر استيرادهما في source graph التقليدي.
- `public/sw.js`: migration kill-switch مقصود لتنظيف Service Workers القديمة، وليس worker مسجلاً في النسخة الحالية.
- `scripts/optimize-images.mjs` و`scripts/process-hero.mjs`: أدوات تشغيل يدوية موثقة في README/CHANGELOG وليست runtime imports.
- `npm ls --depth=0` يعلّم `@img/sharp-wasm32` و`@emnapi/runtime` و`tslib` كـ extraneous؛ التحقق من `package-lock.json` يثبت أنها optional platform/WASM dependencies تابعة لـ `sharp`، وليست dependencies مضافة إلى manifest ولا كوداً ميتاً. لم تُحذف يدوياً حتى لا تُكسر بيئات Sharp المختلفة.

تم حذف exportين مثبت أنهما غير مستخدمين داخلياً (`GA_MEASUREMENT_ID` المكرر في `analytics.ts` و`topicSatellites` غير المستدعى). لم يُحذف أي ملف له مسار تشغيل أو دور migration مثبت.

## مخاطر متبقية مصنفة

### متوسطة — تشغيلية/نشرية وليست ثغرة مؤكدة في الكود

- rate limiting ما زال in-process؛ لا يعطي حداً موحداً عبر عدة instances. عند ارتفاع الحجم يلزم Redis/KV أو WAF.
- نشر `google-apps-script.gs` وإعداد `WEBHOOK_SECRET` و`REVIEW_READ_TOKEN` وtrigger التنظيف يحتاج إجراءً خارج Git.
- فحص claims الطبية بالـ Gemini يتطلب `GEMINI_API_KEY`؛ لا يجوز اعتبار غياب المفتاح نجاحاً، والvalidator الجديد يرفض غياب marker.

### منخفضة — خارجية

- ScienceDirect يرجع 401/403 للـ crawler، لكنه URL واحد معروف ومصنف bot-blocked، وليس دليلاً على dead link.
- انتشار الموقع وSearch Console وMerchant Center لا يمكن إثباته من build المحلي؛ يلزم مراجعة GSC/diagnostics وإعادة إرسال sitemap بعد كل نشر جوهري.

### غير مؤكدة / لا تُعامل كعطل

- لم يظهر mismatch بين `ga-loader.js` وcache version؛ الفحص الحالي يثبت تطابق `67/67`.
- لا توجد حالياً أدلة على broken internal references أو JSON-LD invalidity؛ فحص OSV للحزم المقفلة أعاد 0 finding. تعذر npm audit نفسه بسبب endpoint npm retired (موضح في جدول الاختبارات).
